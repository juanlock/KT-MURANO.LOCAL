#692 Completed Question: can Murano restrict access to listed networks (IP allowlist)? Not today (Login Devices only records). Proposed: per-company setting with IPs / ranges, enforced at sign-in and on eve
Requested Fri, Oct 16, 2026 · 9:13 AM · at Thundera · Category: question · Company: All companies
Request
Jarvis.. murano could be have a feature to enable ip verifications.. and if network not are on list .. cannot access?
Understood as
Feasibility of an IP / network allowlist: only listed networks can access Murano.
Solution

Murano doesn't have this today. The closest is Login Devices, which records where each login came from but doesn't block anything. It's very doable, and fits how Murano already works. How I'd build it: per company, a new setting under System Settings -> Defaults, "Allow access only from these networks" (office IPs or ranges, e.g. 203.0.113.10 or 203.0.113.0/24). Checked on the server at sign-in ("You can't sign in from this network.") and on every request, like the disabled-login check. Exceptions: the SuperAdmin is never blocked; exempt roles or users (e.g. Ruba's operators on phone data in the field); customer portal, online booking and public websites stay open. Lockout protection: the page shows your current IP and warns before you save a list that blocks yourself. Blocked attempts recorded in the Login Activity report. To know: most offices have one public IP; if the provider changes it people get blocked until the list is updated -- a static IP avoids that; on production Murano must read the real IP through Hostinger's proxy (small server setting, tested first). Useful extra: clock in / out only from the office network. Want me to build it? Tell me which company first and which roles or users are exempt.

What changed
No changes (question). Checked: no IP allowlist exists; user_login_sessions / Login Devices record logins only.
