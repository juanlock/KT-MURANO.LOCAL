Solution

Our date range filter is now a project standard, and Preparate loads it at the start of every session.

The rule (CLAUDE.md → Frontend Conventions, and Preparate step 1):

  • Every list, report or dashboard that filters by a date range uses our filter:
  • the preset buttons (All, Today, This Week … Last Year; double-click to set your default ★; a dropdown on phones);
  • plus the editable Start date … to … End date fields.
  • Never a plain calendar range picker, separate From/To pickers, or a new home-made filter.

Which component to use:

  • PresetRangeFilter: the default for any new page.
  • DateRangePicker: for reports that keep dayjs dates or need hours (it uses the same filter inside).
  • DatePresetButtons + DateRangeFields: only for the pages that keep their own preset logic (Sales, Purchases, Customers, POS Sales, Bookings, Payments report, Dashboard).

The rule applies to new pages and to any old page we touch. Date fields where you type data in (a contract's start/end, a leave, a holiday) are not filters and keep the normal date picker.
