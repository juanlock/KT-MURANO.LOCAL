Solution

The employee create and edit forms now have an Other modules card with + Add to Sales Staff and + Add to Sales Agent buttons. Once added, each shows a green tag and a Remove option. Like the rest of the form, changes are saved when you click Submit.

I tested add, remove and re-add on employee 78 inside a transaction that was rolled back, and all worked. The frontend build passed. I haven't clicked through the form in a browser.

  • Sales Staff: Murano had no such concept, so I created one as you chose. Sales Staff are the people offered in the Seller / Salesperson picker on the sale form and in the POS (when Change Salesperson is on in Settings). It's stored in a new users.is_sales_staff column.
  • Sales Agent: adding creates a Commissions sales agent linked to the employee's login. If an agent with the same email already exists without a login link, it reuses that one. Remove deactivates the agent and doesn't delete it, so commissions and receipts stay.

Things that behave differently now:

  • Existing staff were flagged automatically. The migration marked every active staff login as Sales Staff, so the POS picker lists the same people as before. Employee 78 (Edward Lock) will therefore already show "Sales Staff ✓".

  • Inactive agents no longer appear in the Sales Agent dropdown on sales. Before, the dropdown ignored the active flag, so a removed agent would have stayed selectable. Editing a sale still shows the agent and seller it already has.
  • The POS seller check is now limited to the acting company. Before, it didn't check the company.
  • A seller no longer needs an enabled login. Being flagged as Sales Staff is now what counts. A disabled user stays in the picker until you remove them from Sales Staff.

For your other machines: run php artisan migrate. The new migration is 2026_10_04_120000_add_is_sales_staff_to_users.

Admin users who have no employee record can't be added to or removed from Sales Staff, because the buttons are only on the employee form. A Sales Staff switch on the Users form would cover them; I can add one if you want.

#392 Completed Dashboard filters: double-click a choice (date preset, Location, Currency) to make it your default (★), saved per user.
Requested Sun, Oct 4, 2026 · 12:49 AM · at Optimum · Category: feature · Company: All companies
Request
to this filter add feature to double click over any option and this will be default..
Understood as
On the Dashboard filter bar, double-clicking a filter choice saves it as the default the Dashboard opens with.
Solution

You can now double-click a Dashboard filter choice to make it your default. The build passed, but I haven't tried it in a browser, so please give it a quick test.

  • Date preset: double-click a button, e.g. "This Month". On phones, double-click the date dropdown.
  • Location: pick a location (or All), then double-click the Location box.
  • Currency: double-click the Currency box. It only appears when Multi-Currency has more than one currency.

How it behaves:

  • The default is marked with a yellow ★, and a short message confirms each change.
  • Double-clicking the same choice again clears it.
  • Hovering over a filter shows a hint.
  • Defaults are saved on your user account, so each user has their own and they follow you to any PC.
  • The Dashboard now opens with your defaults instead of Today / All locations.
  • If your default location is no longer available to you, it falls back to All.
  • The Location list is now alphabetical with All first, following the dropdown rule.

For Location and Currency, the double-click works on the box itself, not inside the open list. The first click of a double-click picks the option and closes the list, so pick first and then double-click the box. Double-clicking also opens and closes the list for a moment.

The change is in [Dashboard.vue](resources/src/pages/Dashboard.vue), and the request is logged in kt_logs as #392.

What changed
Dashboard.vue: users.ui_preferences key dashboard_filter_defaults {period, warehouse_id, currency_id}; initial period/warehouseId/view currency from it; dblclick wrappers on preset buttons, mobile preset select, Location select, Currency select (toggleDefault); ★ on default (StarFilled in buttons, suffix in select labels); unavailable default Location falls back to All; warehouse options sortByLabel.
