#318 Completed Create/Edit Booking and the calendar modal now use the online form's visual day + time-slot picker (staff can still override).
Requested Wed, Sep 30, 2026 · 10:38 PM · at Home · Category: feature · Company: All (tested on company 3)
Request
http://kt-murano.local/next/bookings/create . all booking create.. should be have same features to select date and time.. like http://kt-murano.local/next/bookings/create . return older version to select date, and time.. this new version is no visual helper (mid-turn) use code for select date and time from this http://kt-murano.local/next/bookings/online and apply to create and edit booking
Understood as
Create/Edit Booking (and every staff booking screen) must pick date and time with the visual day-strip + time-slot picker of the online booking form, replacing the plain date/time inputs Thundera introduced (BookingWhenFields).
Solution

Create Booking, Edit Booking and the calendar's appointment window now pick the date and time the same way as the online booking form: tap a day, then tap a time.

What changed: Thundera's update today had moved these screens to plain date and time boxes (BookingWhenFields). I rebuilt that one shared component as the visual picker, so all three screens got it at once:

  • Day row: 7 day buttons (weekday, date, month), with ‹ › for the previous or next week and a small calendar icon to jump to any date. Today's date is underlined, and closed days are greyed out and marked "Closed".
  • Time buttons: grouped into Morning / Afternoon / Evening, following the company's online booking hours and slot length from Settings → Defaults → Booking. Only start times where the selected service fits before closing are shown.
  • Booked and past times are marked: booked ones are crossed through with a dashed border and an "Already booked" tooltip, and past ones are faded.
  • Summary line: "✓ Thursday, October 2 · 10:00 AM – 11:00 AM (1 h)". The end time still follows the service's duration.

Staff keep full control, unlike the public form:

  • They can still pick a booked or past time, or a closed day. A yellow note then says what's unusual ("this time overlaps another booking… You can still save it").
  • Other time… opens the exact Start / End time boxes for anything off the grid. It opens by itself when an existing booking has an off-grid time.
  • When editing a booking, its own time doesn't show as booked.

Under the hood:

  • The opening hours and booked-times logic moved into one shared place, [BookingAvailability.php](app/Support/BookingAvailability.php). The public form now uses it too, so both pickers always agree.
  • A new endpoint, GET bookings_availability, feeds the staff screens. It uses the acting company, or the customer's company when a SuperAdmin hasn't picked one.
  • The picker itself is [BookingWhenFields.vue](resources/src/components/BookingWhenFields.vue).

Checked:

  • The endpoint returns company 3's hours and booked times; excluding booking #77 while editing it drops it from the booked list (2 → 1).
  • The public form still renders its picker after the refactor.
  • The build passes.

I haven't clicked through the new picker in the browser. Please try /next/bookings/create and the calendar.

What changed
BookingWhenFields.vue: plain date + start/end time pickers -> visual picker: 7-day strip (paging, jump calendar, closed/today marks), time slots by company hours/slot length fitting the service duration, grouped Morning/Afternoon/Evening, booked (dashed, struck) and past (faded) slots still selectable with a warning, summary line, 'Other time…' exact start/end inputs (auto-open for off-grid times); props excludeId, customerId; same v-model:date/start/end + duration API. App\Support\BookingAvailability (new): hours(), busy(), maxConcurrent() shared by public + staff pickers. PublicBookingController: hours/busy/maxConcurrent delegate to it (behaviour unchanged). BookingController::availability + route GET bookings_availability (hours, busy, today, now_min). BookingForm.vue / BookingCalendar.vue: pass exclude-id and customer-id to the picker.
